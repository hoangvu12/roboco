### `037f4c10` (#820) — wave ticket

The "Latest turn" snapshot ran `git add -A` under a throwaway index, which
writes a blob for every unignored file into the checkout's own
`.git/objects` — nothing referenced or bounded them, and the add had no
timeout; an affected checkout collected 20 GB of loose objects and 23
concurrent git pack-objects (117 GB) after agent commits. Each snapshot now
writes into its own object directory under the data dir (checkout DB as
read-only alternate, absolute paths because git resolves
GIT_OBJECT_DIRECTORY against the checkout), deleted with the snapshot and
swept at start; turn-diff captures layer on the turn's snapshot so they only
write what changed. Snapshots are bounded (untracked files > 8 MiB and
untracked dirs > 10 000 files or 256 MiB left out, largest-units-first over
budget), run under a 120 s timeout with kill-on-drop children, and are
dropped when the chat is gone/archived without a viewer or its cwd stops
being a checkout.

Roboco inherits the exact bug: `snapshot_tree`
(`crates/engine/src/diff_sync.rs:1655`) runs `git add -A --ignore-errors`
(`diff_sync.rs:1673`) through `cmd.output()` with no timeout, writing into
the checkout's own object database. Five
files, all in `crates/engine` (`diff_sync.rs` +164, new
`diff_sync/turn_snapshot.rs` +1069, `lib.rs`, `rpc.rs` +27,
`m5_repos_diffs_terminals.rs`), zero excluded surfaces, no wire change.
Roboco's own `diff_sync_churn.rs` engine tests (from the #605 port
`55593697`) coexist with upstream's new 330-line churn file — reconcile by
intent.

### `91fd851c` (#748) — wave anchor, do not port blind

One squash of 30+ commits. The adapter lifecycles are rebuilt around a
persistent runtime: **Stop is the one teardown** (ends the turn and the
whole runtime including shells the CLIs started in their own process
groups — descendant-tree snapshot, killed after the agent), while sends,
steers, "send now" and model/effort switches keep the runtime alive
(Claude adopts new config with `set_model`/`apply_flag_settings`, Codex on
the next turn/start). Premature "done" is fixed at the boundary: every
stdin user line carries a uuid and Claude's `command_lifecycle` frames
decide turn end (a result while one of our messages is still
written/queued is a boundary, superseded when that message starts); Codex
settles only the turn in flight (stale/duplicate completions ignored,
steers confirm on `clientUserMessageId`, a stop waits for `turn/started`).
Stop/send ordering is serialized (a stop can't run before a send queued
ahead of it; late arrivals re-dispatch). New `TurnControl`
(stop-in-place vs teardown, background-work counter holding the idle
reaper) and `SteerMessage` gains `attachments` + carried `config`.
OpenCode: rejected stops tear the runtime down, queued images preserved.
Tests: fake-CLI scenario fixtures (`fake-claude.sh`, `fake-codex.sh`,
`fake-acp.sh`), a chaos suite, opt-in live suites (30/30 Claude Sonnet
5.5, 30/30 Codex gpt-6-luna).
