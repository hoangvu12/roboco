## Port candidates, most valuable first

### #800 Claude context usage for custom models (FIX-CANDIDATE, S–M)
- **What users see:** with a custom Anthropic-compatible gateway model, the context ring sits at 0%. A folded `[1m]` model shows "1M" in the picker but runs at 200K, so auto-compact also triggers at 200K. Upstream bug #786 is still open, and upstream main has the same code.
- **What's missing:**
  - Default option values are not sent with the run: the folded `contextWindow=1m` default at `ui/src/pickers.rs:5778` needs to reach `RunRequest.model_options`. Either materialize offered defaults in the composer's run payload, or write the default into the chat config when the chat is created. The PR's own follow-up note says the second covers the engine restart+steer path (`request_from_chat_row`) and the mobile client as well.
  - `harness/src/claude/normalize.rs`: treat `message_start` and `message_delta` usage (parent only, positive only) as measurements, and stop an all-zero aggregated `assistant` frame from publishing `Some(0)`.
  - The result `modelUsage` lookup should try `<model>[1m]` before the single-entry fallback.
- **Files:** `harness/src/claude/normalize.rs`, `claude/wire.rs`, `ui/src/composer.rs`, `ui/src/pickers.rs`. No wire change.
- **Risk:** low. The PR diff (#800) is self-contained and has tests.

### #917 (Windows slice) Preview discovery re-reads every process's environment every 2 s (FIX-CANDIDATE, S–M)
- **Why it matters:** Roboco's own Windows scanner (889ffc1b0) runs `System::new()` plus `refresh_processes_specifics(All, cmd|cwd|environ)` every 2 s (`preview/src/discovery.rs:847-859`, loop at `service.rs:368-369`). That opens and reads the PEB of every process on the machine, all day, even with no agent, terminal or Browser tab. Upstream's fix (#917) was for macOS/Linux and never landed; #1023 only narrowed which ports are listed.
- **Fix:** refresh only the pids that own loopback sockets plus their ancestor chain (`ProcessesToUpdate::Some`), or keep one long-lived `System` so `OnlyIfNotSet` actually caches. Separately, park the loop while the engine has no live descendant (#917's idea), and wake it on run dispatch or terminal open.
- **Risk:** low. Keep the unreadable-PEB degradation from ticket 02. **Measure first** (Process Explorer CPU and I/O on the engine with no previews).

### #741 / #742 Hide shell launch wrappers in Run titles (FIX-CANDIDATE, M)
- Already written up in `part-prs-B.md` (#742). Windows Codex titles show `powershell.exe -Command …`.
- #741 adds a shared `proto::command_display::display_command` that unwraps PowerShell, cmd and Unix shell wrappers, and wires it into `view.rs` `tool_chip_content`, `ui/src/transcript.rs`, and `mobile/src/layout/tools.rs` (Android gets it for free).
- Port one of the two PRs, not both.

### #428 Cursor usage by model pool (FIX-CANDIDATE, S)
- `cursor_usage_window` (`engine/src/agent_accounts.rs:4465`) should prefer `planUsage.autoPercentUsed`/`apiPercentUsed` as two windows ("Cursor Models" and "Other Models") when they are present, and keep spend/limit for older responses.
- Check against a current `GetCurrentPeriodUsage` payload before porting; Cursor's API has drifted before.

### #659 leftover: Windows hint in the New project palette (FIX-CANDIDATE, S)
- `ui/src/shell/spaces.rs:7613` should say e.g. `Type a path like C:\code or ~\code to jump there.` when the browsed device is Windows. The palette already knows this through the `windows` flag used at `:6818`.
