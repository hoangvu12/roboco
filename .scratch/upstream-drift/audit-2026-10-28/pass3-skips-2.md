## New gaps

### G1 — Forking a chat on a paired engine: open the tab at once, with progress, error and Retry; show an "Opening…" loader for slow remote chats (from `00cc2e059` #1038)
- **What users see today:** you fork a chat that lives on another of your engines, for example a server reached over Tailcat. Nothing happens until that engine answers. Meanwhile every other fork or new side chat, anywhere, is silently ignored. If the fork fails you get a passing notice, with no Retry. Separately, opening a chat on a slow paired engine shows an empty transcript until its history arrives.
- **Upstream shape to carry over** (the parts that don't depend on edge):
  - `PendingFork { params, host, error, running }` per side-chat tab, plus `run_fork` / `retry_fork` / `finish_fork` and `draft_child_row`, in `crates/ui/src/shell/side_chats.rs`. The tab's empty state reads "Forking on {host}…" or "Couldn't fork on {host}", with the engine's reason and a ghost Retry. Retry replays the same `chatId`, so it is idempotent.
  - `TranscriptLoading::Opening` plus the delayed `render_loader` in `crates/ui/src/transcript.rs`. Gate it on "chat not hosted by the local engine and `!transcript_replayed`". Upstream's `Syncing`/`Stalled`/`Offline` states would map onto Roboco's per-engine `EngineConnectionState` (`settings/devices.rs:41`) instead of edge `ConnectivityState`.
- **Roboco files:** `crates/ui/src/shell/side_chats.rs:57-117`; `shell.rs:1833` and `fork_dialog.rs:137` (replace the global `side_chat_creating` flag); `session_lanes.rs:375`; `state.rs`; `transcript.rs`.
- **Wire:** none (`FORK_SIDE_CHAT` is unchanged). The fork id must be minted client-side before the call; Roboco already does this (`uuid::Uuid::new_v4()` at `side_chats.rs:83`). Scope the draft row to the engine (`engine_registry::scope_chat`).
- **Effort:** M. Do the fork tab first; the loader is S on its own.

### G2 — The Android core build likely compiles `roboco-mobile` twice for the host (from `684becf0f` #609, `crates/mobile-bindgen`)
- **Effect:** slower `android.yml` / `release.yml` / local Gradle core builds. Users see no difference.
- **Why:** `cargo xtask android-core` builds the `uniffi-bindgen` bin out of `roboco-mobile` with `--features bindgen,<lang>`, which turns on `uniffi/cli`, then builds `--lib --features <lang>` (`crates/xtask/src/main.rs:133-175`). The two feature sets differ, so `uniffi` and `roboco-mobile` (lib + cdylib, LTO under `mobile-dist`) are built twice. The "feature-matched … reuse each other's artifacts" comment at `main.rs:130` doesn't hold for the bindgen feature. Upstream moved the generator into its own crate (`crates/mobile-bindgen`, `uniffi = { version = "0.32", features = ["cli"] }`, `fn main() { uniffi::uniffi_bindgen_main() }`). That crate must pin the same uniffi version as `roboco-mobile`.
- **Check first:** time `cargo xtask android-core` with `-v` and look for two `Compiling roboco-mobile` lines.
- **Files:** a new `crates/mobile-bindgen/` (`roboco-mobile-bindgen`), workspace `Cargo.toml` members, `crates/xtask/src/main.rs`, and dropping the `[[bin]]` and `bindgen` feature from `crates/mobile/Cargo.toml`.
- **Effort:** S.
