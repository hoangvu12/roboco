## 4. The memory ceiling, in detail

- **Why ≈ 3 builders.** Windows does not overcommit. Every `rustc` reserves commit charge, and the system limit is RAM + pagefile ≈ 40 GB. A 20-thread cargo build of the gpui/UI graph runs many `rustc` processes at 1–6 GB of commit each. The event log shows triples of 3.4–3.6 GB `rustc` plus `link.exe` at 3.7 GB, so 2–3 such builds (plus Roboco, browsers and Discord) reach the limit. The result: error 1450/1455, `rustc` crashes, and once (R2) an unclean shutdown that corrupted git files.
- **The fix,** in order of effect:
  1. pagefile from 8 GB fixed to system-managed or 48 GB;
  2. `jobs = 8` per build;
  3. warm lane worktrees, so most builds are incremental;
  4. LLD (lower link commit and time).

  `debug = "line-tables-only"` is already set. `split-debuginfo` doesn't matter on MSVC (PDB). Dropping deps from `opt-level 2` to 1 would cut memory a little, but it slows gpui at runtime and invalidates every cache: not worth it.
- **Memory-aware scheduling** (product, §6) would make this automatic: the engine refuses to start another heavy build when commit charge is above about 80 % and queues it instead.

User-gated items sit outside these numbers: the 57 fork push, 44's design check, fleet 11/15/16 real-device checks, and the web-removal 11 checklist. Batch them into one daily checklist message.

## 7. Decisions the user would need to make

1. **Pagefile:** set it to system-managed (or 48 GB) on C:. Needs admin and a reboot. Recommended.
2. **Build parallelism:** 4–5 concurrent building workers with `jobs = 8` each (parent-folder cargo config; it also applies to kyoko). Recommended.
3. **Persistent lane worktrees** (`roboco-lane-1..5`) instead of a new worktree per ticket. This replaces the "remove its worktree" part of the cleanup rule. Recommended.
4. **Install the Android SDK/NDK** locally (≈ 6–10 GB). Recommended.
5. **Branch protection + auto-merge on green** for `main`, with the required checks already chosen in ci-speed. Recommended.
6. **Raise the sccache size** to 50–60 GB (shared with kyoko). Recommended.
7. **Use the PC:** open lane chats on it by hand now, and/or move fleet-redesign 12–13 earlier. Self-hosted runner: not now (public-repo risk).
8. **Usage limits:** allow Sonnet or lower effort for mechanical tickets (CLEAN/TRIVIAL ports, docs, CI YAML), or a paid plan upgrade (**paid**), or accept the occasional stall.
9. **Standing OKs that remove round-trips:**
   - deleting `bisect/*` and `ci/scratch-*` branches after use;
   - the W57 fork push at its sync point (it waits on a decision today).
10. Optional: Defender exclusions or a Dev Drive for the lane worktrees.

## 8. Caveats

- Local build RAM and time were **not** measured: other builds were running all session. Ticket 18 (`cargo --timings`) and one quiet-machine measurement should confirm the `jobs = 8` and LLD numbers before they are written into docs.
- The chat timeline covers only the last ≈ 22 h of orchestration. Stall frequencies are extrapolated from one day.
- Hour savings are estimates, built from the measured per-event costs × the expected number of PRs and spawns. They overlap: for example, auto-merge saves less once the orchestrator is reliably available.
