## The model in one paragraph

A room = shared **secret + address book** (the invite *is* the room
serialized: `roboco-room:<base64url(json{v,name,secret,members[]})>`).
Hostless: no engine in charge. **Engines join** by consuming the invite →
they store only a SHA-256 verifier (CLI `roboco engine room join '<invite>'`
or the desktop Settings action). **Clients join** by dialing each book
member over Tailcat and POSTing the secret to `/room/present` → they get an
ordinary session per member, and members appear as ordinary paired engines.
Capability-gated: engines advertise `rooms-v1`; old engines → room UI hidden.

## Likely suspects for "confusing / doesn't work" (from implementation knowledge)

1. **Tailcat prerequisite is silent-ish**: every member engine must serve
   Tailcat (remote access enabled + Tailcat transport). The desktop create
   flow SKIPS engines without it into an "unavailable" list ("enable its
   Tailcat route first") — easy to miss. No Tailcat → nothing dials.
2. **Create ≠ everyone's in**: the create flow mints the invite and hands it
   over; it does NOT push anything to members (hostless semantics). Each
   engine must separately join (CLI/Settings). If the user expected
   create-and-done, the room looks dead.
3. **Second PC's engine address only enters the book** if it was seeded at
   create (from a PC that has it paired) or added via rotate/re-share.
   Otherwise PC 2's *client* joins, but nobody can dial PC 2's engine as a
   member.
4. **Desktop-paired engines don't survive a desktop restart** (pre-existing
   registry limitation); the room card's **Reconnect** re-dials.
5. **Partial joins heal only on app open / network change** (no liveness
   probing by design) — a sleeping member stays offline-looking until then.
6. **The invite is a secret** — QR/copy only from the invite card; if the
   user pasted it somewhere logged or shared it widely → rotate.
7. **100 MB uploads** need BOTH ends on v0.13.0 (engine capability
   `uploads-100mb-v1`), else silent clamp to 24 MB.
