# Removing the web client: impact map (2026-10-28)

Read-only research on `feature/fleet-follow` (HEAD `7df761c7f`, 107 commits ahead of `main`; `main` is an ancestor). Nothing was changed.

## Answer

"The web" is a **Roboco-only** React client (ADR 0006, ADR 0007). The engine compiles it into its own binary with rust-embed and serves it at its remote-access URL, so a browser can pair and drive an engine without installing anything. Upstream zeron has **no `web/` tree** and **no ts-rs**, so `git log upstream/main --since=2026-09-15 -- web/` returns **0 commits**. The cost comes from Roboco keeping a third client in parity with the other two, not from upstream conflicts. Nothing on the desktop or Android depends on the web *app*. Three non-web things do touch the web *tree*, and each is easy to cut loose:

1. Three Android JVM tests read `web/packages/theme/src/generated/artifact.json` and use it as their repo-root anchor.
2. Release builds of the engine `panic!` when no web bundle is present (`crates/engine/build.rs`).
3. The `/preview-relay` route also has a browser-only auth branch alongside the native one.

The engine endpoints that native clients use (`/pairing/redeem`, `/room/present`, `/health`, the WebSocket RPC at `/` with Bearer auth, `/preview-relay` with Bearer auth, the `/pair#token=` link grammar, `uploads-100mb-v1`, `rooms-v1`/`rooms-v2`) are **shared and must stay**.

The real loss is **browser access to an engine from a device with no Roboco install**: an iPhone or iPad (Roboco has no iOS client), a borrowed or work PC, or any browser reached over a Cloudflare tunnel. The browser room-join relay goes with it.

**Recommendation: Option C.** Remove the web client and every browser-only engine surface. Keep the shared endpoints. Move the theme artifact to a non-web path for Android. Optionally keep a tiny static `/pair` landing page. Tag `web-final` first so the code can be recovered. This deletes about **203k text lines and about 1,440 files under `web/`**, plus **about 3.1k lines of Rust**. It edits about 240 lines of `#[derive(TS)]` / `ts_rs` annotations, about 5 CI workflows and 3 packaging scripts. It drops Node/pnpm from the release pipeline entirely.

**Timing:** do this after the in-flight release publishes and after `feature/fleet-follow` merges. That branch carries 20 changed `web/` files (+868 lines), including the preview panel.

Note: the status note at the end of ADR 0011 says the browser relay (`/pairing/room-redeem`) and the 100 MB cap were "not re-landed". That note is **stale**. Both are in the code, and the fleet-follow handoff confirms they came back with the v0.13.0 merge.

## 3. What removal deletes, edits, and risks (Option C)

**Deletes**

- `web/`: ≈203k text lines, 1,437 files.
- Rust: `crates/wiregen` (618), `crates/engine/src/web.rs` (40), `crates/engine/src/tailcat_relay.rs` (708), `apps/roboco/src/tailcat_browser_helper.rs` (149), `tests/web_client.rs` (409), `tests/room_relay.rs` (658), `examples/web_{conformance,smoke}.rs` (114), placeholder pages (146, unless kept as the landing page).
- About 250 lines inside `listener.rs`, `build.rs`, `preview_relay.rs` and `lib.rs`.
- **Rust total ≈3.1k lines.**
- CI: `web-codegen.yml`, `web-engine-client.yml`, the theme TS job (≈200 lines).

**Edits**

- 20 Rust files to strip ts-rs (≈220 lines), plus `Cargo.toml` × 6 and `Cargo.lock` (`ts-rs`, `rust-embed`).
- Engine tests (≈150 lines).
- `release.yml`, `windows.yml`, `ui-tests.yml`, the packaging scripts.
- Relocate `roboco-theme-export` output and update 3 Android tests plus `TestRepoRoot`.
- Docs and ADRs listed above. `AGENTS.md`.

**Risks and lost features**

- **No zero-install access.** Without the web client, a phone or computer needs the Roboco app to reach an engine. Lost cases: iPhone/iPad (no iOS client exists), a borrowed or work PC, and any Cloudflare-tunnel-in-a-browser use. This is the only user-facing loss, and it is total for those devices.
- **Browser room join is gone.** Fleet follow never had a web path, so nothing current regresses.
- **System-camera QR scans.** Scanning the desktop's pairing QR with the phone's *system* camera currently opens `/pair` in a browser. After removal it would 404, unless a static landing page is kept. That page could tell the user to share the link into the Roboco app; `PairShareActivity` already accepts `text/plain` shares. The in-app scanner is unaffected.
- **Lost coverage.** The TS conformance suite exercises the real engine wire protocol from a non-Rust client. Losing it is minor, since Android's core and the Rust tests cover the protocol.
- **Wire-type freshness gate.** It disappears along with its only consumer, so there is nothing left to go stale. The Android/UniFFI surface is Rust-typed and compiler-checked.
- **Stale on-disk state.** Old engine data dirs may hold `tailcat-relays/` directories and browser sessions in `pairing.sqlite3`. Both are harmless: the sessions stay listed and revocable, and the directories could be cleaned up once.
- **Stale reference comments.** The 47 comments citing `web/…` go stale. A `web-final` tag preserves them.
- **Reversibility.** ADR 0006 notes that a separately hosted client "remains possible later". Re-adding it means restoring from the tag and re-adding the browser surfaces. The `web-final` tag keeps that cheap.

## 4. Options

| Option | What | Pros | Cons |
|---|---|---|---|
| **A. Freeze** | Delete `web-codegen.yml`, `web-engine-client.yml` and the theme TS job. Leave code. Keep building the bundle in release (or set `ROBOCO_WEB_DIST` to the placeholders so release stops needing Node). | Tiny diff. Fully reversible. | ts-rs derives, wiregen and 176 annotations still ride every wire change. The generated TS silently drifts, and the web breaks against new engines while still shipping in the binary (or ships as a placeholder page). Port tickets still ask "web too?". It is a slow-motion removal with dead code left behind. |
| **B. Remove the app, keep browser plumbing dormant** | Delete `web/`, wiregen, ts-rs, rust-embed and asset serving. Keep CORS, first-frame auth and the Tailcat/room browser relay in the engine. | Keeps the door open for a separately hosted client. | About 1.7k lines of security-relevant code (pre-session CORS routes, relay dials) stay with no client and no tests that matter. That attack surface serves nothing. |
| **C. Remove everything browser-only (recommended)** | B, plus drop CORS, first-frame auth, `/pairing/{tailcat,room}-redeem`, `/tailcat-relay`, `browser-helper`, the `web-client` capability. Reject Origin on the paired bind too. Relocate the theme artifact. Optionally keep a static `/pair` landing page. | Largest simplification. No Node in release. Smaller binary. Smaller pre-session attack surface. Wire changes become Rust-only. Ports carry intent into 2 clients, not 3. | Loses zero-install browser access, including iOS devices. Largest diff (mostly deletions). |
| **D. C, and also drop the theme artifact** | Delete `roboco-theme-export`, `artifact.rs` and its tests, and the Android pin tests. | About 830 more Rust lines and one fewer workflow. | Loses the guard that catches desktop/Android palette drift. Not worth it: relocating the artifact is cheap. |

## 5. Upstream ports and CI

- **Upstream:** 0 of 613 upstream commits since 2026-09-15 touch `web/`, because upstream has no web client and no ts-rs. Removal causes **no merge-conflict reduction on `web/` itself**. The savings are indirect:
  - **Fewer conflict sites.** 100 of those 613 upstream commits touched the 15 upstream files that carry Roboco's `TS` derives. Each is a potential derive-line conflict plus a mandatory `cargo run -p wiregen` regen, `shims.ts` touch-up and `web-codegen` gate.
  - **Fewer parity tickets.** Port waves have carried intent into the web as a third client: wave 3 had 15 of 21 tickets mentioning web, wave 4 26/31, wave 5 10/11, wave 6 2/3, wave 7 6/22, wave 8 1/13, wave 9 0/24. The cost was concentrated in early waves and is falling.
  - **Less Roboco-side churn.** 490 of 2,188 Roboco commits since 2026-09-15 touched `web/` (205 in the last 30 days; 61 of 472 since 10-15). 75 were regenerating `proto/src/generated`.
  - **Smaller drift audits.** The current drift audit (`.scratch/upstream-drift/2026-10-28.md`) lists web as an affected client in A15 and A35.
- **CI jobs removed:**
  - `web-codegen` (1 job, ~1.5-7 min)
  - `web-engine-client` (2 jobs: `engine-client` + `web-smoke`, ~6-8 min)
  - the `@roboco/theme` typecheck job

  These were 3 of the 13 job names green in the fleet-follow handoff. `release.yml` loses Node setup + `pnpm install` + Vite build in both the linux and windows jobs. `windows.yml` and `ui-tests.yml` lose the `ROBOCO_WEB_DIST` workaround.

## Removal checklist (Option C)

Do this on a branch from `main` after the release publishes and `feature/fleet-follow` merges. One PR, ordered so each step builds.

1. `git tag web-final <main sha>` and push the tag. This preserves the client, the browser plumbing and the parity notes.
2. **Theme artifact first** (keeps Android green):
   - Move the `roboco-theme-export` default output from `web/packages/theme/src/generated` to e.g. `crates/theme/artifact/artifact.json`.
   - Drop the font-copy entries that only the web used (`artifact.rs` `fonts`/`FONT_FACES`; schema bump if the shape changes).
   - Update `crates/theme/tests/artifact.rs`, `TestRepoRoot.kt` (anchor), `ThemeArtifactPinTest.kt`, `ProjectTonesPinTest.kt`/`ProjectTileTest.kt` if they reference the path, and `.gitattributes`.
   - Trim `theme-artifact.yml` to the Rust job and fix its paths.
3. **Engine build:** delete the web staging from `crates/engine/build.rs` (keep `embed_tailcat_adapter`). Delete `src/web.rs`, the `rust-embed` dependency and the `web-staging/` gitignore line. Either delete `assets/web/` or keep one static `pair.html` served by `include_str!` at `GET /pair`.
4. **Listener** (`crates/engine/src/listener.rs`):
   - Remove the asset routes, SPA fallback, `RESERVED_API_PATHS`, CORS preflight, `cors_open`, `/pairing/tailcat-redeem`, `/pairing/room-redeem`, `/tailcat-relay/*`, and `authenticate_first_frame`/`refuse`/`first_frame_auth`.
   - A Bearer-less upgrade becomes 401.
   - Keep Local-bind Origin rejection. Optionally reject Origin on the paired bind too.
5. Delete `src/tailcat_relay.rs` and its wiring in `lib.rs` (`PairedListenerContext`, `restore_from_disk`). Simplify `serve_listener_with_policy`'s signature. Remove the `first_frame_auth` parameter from `preview_relay.rs`.
6. **CLI:** delete `apps/roboco/src/tailcat_browser_helper.rs`, `TailcatCommand::BrowserHelper` and `mod tailcat_browser_helper`. Reword the `tailcat connect` help ("loopback pairing link"), and keep the command.
7. **Proto:** remove `capabilities::WEB_CLIENT` from `CURRENT` and its test. Leave fixture JSON alone (stored data may contain the string).
8. **ts-rs:**
   - Delete `crates/wiregen` from the workspace.
   - Strip `TS` from 176 derives, plus 20 `#[ts(…)]` attrs and 24 imports, in `crates/{proto,doc,engine,update}`.
   - Drop `ts-rs` from 5 crate `Cargo.toml` files and the workspace. Refresh `Cargo.lock`.
9. **Tests:** delete `tests/web_client.rs`, `tests/room_relay.rs`, `examples/web_conformance.rs` and `examples/web_smoke.rs`. Edit the browser-path cases in `tests/pairing.rs` (~188), `tests/preview_relay.rs` (~360-420, ~452-570), `tests/remote_listener.rs` (~141) and `tests/rooms.rs` (~558).
10. Delete `web/`.
11. **CI and scripts:**
    - Delete `web-codegen.yml` and `web-engine-client.yml`.
    - Remove the Node/pnpm/web-build steps and header comment from `release.yml` (linux + windows).
    - Remove `ROBOCO_WEB_DIST` and its comment from `windows.yml` and `ui-tests.yml`, and drop `-SkipWebBuild`.
    - Strip the web build from `scripts/package-windows.ps1` and `scripts/package-linux.sh`, and the favicon output from `scripts/generate-app-icons.py`.
12. **Docs:**
    - New ADR 0012 "No web client" (supersedes 0006 and 0007; records the iOS/zero-install trade-off).
    - Amend ADR 0008 (browser bullets) and ADR 0011 (browser relay paragraph; fix the stale status note).
    - Retire the `CONTEXT.md` "Web client" entry.
