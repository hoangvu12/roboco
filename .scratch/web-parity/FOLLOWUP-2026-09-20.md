## Verification discipline for future implementation

- Use the self-contained acceptance matrix in each ticket. Code-proven facts, reproduced failures, passing tests and manual captures are different evidence.
- Preserve the user's **always-opaque web** directive and existing reduced-motion endpoint rules.
- Never represent an unexecuted browser/phone check as passed or waive it because helper tests pass.
- Subagents must not start long-running dev servers, engine runs, smoke processes or browsers. Use an already authorized running application or coordinator/user-provided captures for required runtime evidence.
- Record executable and served bundle identity: the engine embeds web assets at compile time. A current source checkout does not prove that the running executable serves that bundle.
- Standard implementation checks: `pnpm -r build` from `web/`, `pnpm test` from `web/packages/app/`; Rust checks only for actual Rust changes. No such commands were run while writing these tickets.
